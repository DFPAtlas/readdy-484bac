# Guard statements, profile placement and token checkout

22 November 2026. Scope confirmed by Martin: token redemption covers new subscription checkout only. Keep the current tax setup; QuickGuard does not currently collect VAT through Stripe Tax. Live payment/refund remains the final separately scoped test.

## Implemented behaviour

- Payment Centre → Statements downloads a real monthly PDF using the existing PDF library. UK assignment dates select the month; recorded gross, fees, net and transfer status are retained. Only completed transfers enter the paid summary. The document distinguishes transfers from bank arrival and permits an empty monthly statement. Export verifies the same signed-in owner before and after rendering; account changes discard the export.
- Find a Guard and Recommended applicant ordering rank eligible current profile boosts, then priority profiles, then ratings. Explicit client sorts and filters remain effective. Featured badges explain the placement. The RPC exposes only guard IDs and two placement flags; active, completed, recorded-reviewer, current-SIA and entitlement checks apply. It does not expose private plans, billing, documents or contacts. Test profiles get no anonymous placement. The public list accepts both approved and verified status, but only displays profiles admitted by the eligibility RPC; a missing reviewer or invalid SIA cannot be promoted or newly exposed by that change.
- New-subscription checkout can accept approved QG Tokens when its server switch is enabled. Current conversion is 100 tokens = £10, capped at 50% of the first invoice. Monthly/annual catalogue prices remain unchanged. A product-bound, single-redemption, duration-once coupon discounts only the first invoice. Trials, existing subscriptions/plan changes and job payments do not accept tokens.
- A per-user database lock reserves tokens before contacting Stripe. A stable request UUID, coupon ID and provider idempotency keys recover interrupted requests. One pending redemption is permitted per user. The UI shows the first invoice estimate, rejects an oversized selection, and offers resume/cancel controls. A reservation is released only after confirmed expiry/cancellation or terminal asynchronous failure; simply leaving checkout does not release it.
- Signature-verified webhook handling retrieves current Stripe session state, checks owner/metadata and the actual discount, and confirms the reservation once. Replayed confirmation cannot double-spend; a stale failure cannot reverse a paid reservation. The return URL does not grant credits or activate redemption.
- Balance calculation replays grants and spend in FIFO order with the configured grant expiry. Historical spending is not subtracted again from new rewards after an old grant expires. Pending/unapproved grants are excluded; clawbacks and negative adjustments reduce availability. Expiry records are not charged a second time when the grant date already expires a lot.
- Refunds and token restoration remain subject to the existing review process; no automatic cash refund or token restoration was added.
