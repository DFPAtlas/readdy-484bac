# Closed-account free subscription lifecycle repair

The account-closure procedure disabled the client/guard profile and canonical entitlement but left an unbilled free subscription row active. A retained closed client exposed this inconsistency. Its Auth ban, inactive profile and canceled entitlement already prevent access; the active subscription row was stale lifecycle metadata.

## Repair

The migration adds service-only, invoker-rights `app.reconcile_closed_free_subscriptions(uuid)` and calls it from the existing closure procedure after disabling access and on repeated closure requests. It requires an established closure and an inactive matching profile without provider billing identifiers. Only an active catalogue `client_free` or `guard_starter` row for that account type with zero catalogue/recorded price, no amount paid, no provider references, no payment/service-period evidence and no subscription-payment history can change. Other records retain their existing review path. Each changed row receives a `free_subscription_closed` retention event in the same transaction. Cancellation is recorded at reconciliation time; the original closure and retention dates are preserved. Repeats do not duplicate the event.

The existing subscription-to-entitlement trigger now treats account closure as authoritative: it keeps an existing entitlement canceled and preserves its retained plan/features/provider evidence. It does not reconstruct an entitlement for a closed account. This avoids erasing retained details when an older closed account has no `app.users` row. Open-account synchronization is unchanged. No trigger is disabled, no browser permission is added, and the existing closure authorization, membership locks, paid-subscription, booking, dispute and payout safeguards remain.

The separately guarded `scripts/ops/20261122-reconcile-closed-free-client.sql` targets the already-closed client `ecdf41db-1a51-437e-aed9-66078879d9bc`, closure `e7336199-d878-4fef-b439-ab84c017fca3`, local subscription `a6e45d09-f57b-45ed-ade4-3b12c3f77c78`. It checks the original closure date and identity and asserts unchanged full profile, entitlement and closure records, a canceled subscription and exactly one matching retention event. It calls no Auth, Stripe, email, booking or retention-purge API.
