# Admin SIA status labels

The live profile header and lower SIA summary labelled completed `verified` and `valid` results as Pending. Missing profile status also implied a running check, and a manual-review profile could incorrectly imply a missing webhook. `expired`, `not_found` and `verified_test` were not recognised. The manual SIA override path writes `passed` with an override marker, which previously appeared as an automated pass.

One shared display resolver now supplies badge and explanatory text for the header, Overview SIA section and active review modal. Completed, negative, queued/in-progress, error/review, absent and unknown stored statuses have explicit labels. An absent status means Not recorded; the profile's manual-review state alone does not establish a webhook fault. Unexpected status values remain Unknown. Text describes the stored result and directs review of dated register and matching-licence evidence; it does not certify a fresh register lookup or an approval.

Explicit `verified_test` status or the existing `is_test_account=true` flag identifies a test result/account. Positive test statuses have a neutral warning tone. No account is inferred to be a test account from its name, email, activity state or incomplete evidence. A recorded manual-override marker is labelled Manual override and preserves the underlying stored status in its explanation. Positive statuses with a mismatch remain Evidence needs review. Original mismatch details and historical register results remain available; the repair does not clear worker findings.

The five regression groups reproduced the old failures and cover current completed/negative statuses, missing/unknown evidence, independent pending/webhook states, test flags/results, manual overrides and mismatches.
