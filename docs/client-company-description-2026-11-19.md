# Company Description persistence — 19 November 2026

Editing Company Description supplied `clients.description`, which did not exist in the deployed database. The profile form's update could therefore fail with an unknown-column error. An unchanged undefined property could be omitted by JSON serialization, so the defect did not establish that every unchanged profile save failed.

## Change

Migration `20261119212527_add_client_company_description.sql` adds the intended nullable text column to `app.clients`, with no default, backfill or row update. The existing form keeps its editable-field whitelist, client-ID filter, returned-row confirmation and failed-write/Retry handling. The optional description now has a connected accessible label. Company Profile exports explicitly include the saved description in preview, JSON and CSV.

No existing notes field is repurposed and no billing, verification, counter or entitlement field is made editable. No RLS policy, grant, trigger, authentication setting, package or secret is changed. The existing retention function already includes description in its dynamically checked profile-minimisation fields; it needs no production code change.
